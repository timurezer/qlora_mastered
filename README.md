# DeepSeek-V4-Flash QLoRA on current MindSpeed-LLM master

QLoRA fine-tuning pipeline for `DeepSeek-V4-Flash-Base` on Ascend NPUs, restored on
**current [MindSpeed-LLM](https://gitcode.com/Ascend/MindSpeed-LLM) master** (`90f862cd`,
fork branch `dev/qlora_support`). This is the master port of the run-D pipeline from
[qlora_clear](https://github.com/timurezer/qlora_clear) (QLoRA fork on the pre-removal
commit): teacher distillation of `DeepSeek-V4-Flash-0731` into the Base model.

* All experiments were performed on a Huawei Ascend 910B3 64G x8 node.
* The dataset: 14,090 [GSM8K](https://huggingface.co/datasets/openai/gsm8k) +
  [MATH](https://huggingface.co/datasets/EleutherAI/hendrycks_math) answers (up to 4k
  tokens) generated by `DeepSeek-V4-Flash-0731` (`data/base_distill/ds_teacher/`).
* NF4 base (bitsandbytes), LoRA r16/alpha32 on `linear_fc1 linear_fc2`, lr 3e-4, fixed
  `--seq-aux`, full shared-expert adapter.

## Training results

1-epoch distill run on `dev/qlora_support`, evaluated with vLLM (Base-w8a8 + QuaRot-rotated
adapter, TP8 + expert parallel, full GSM8K 1319 + MATH-500, greedy, thinking off):

| model | GSM8K (1319) | MATH-500 (500) |
|---|---:|---:|
| DeepSeek-V4-Flash-Base-w8a8, student (old stack) | 58.53 % | 37.60 % |
| run D reference (old fork, old eval stack) | 95.45 % | 93.80 % |
| qlora_clear reproduction (va30 stack) | 95.68 % | 93.40 % |
| **master dev/qlora_support (this repo)** | **95.91 %** | **92.60 %** |
| master, memory opts on (chunk 16) | 95.45 % | 93.20 % |

Master reproduces run-D quality; MATH-500 differences are within the known ~1-2 pt eval
stack noise.

Details:
* The training checkpoint is obtained from the original FP8 checkpoint dequantized to
  bf16, not from the `w8a8`-quantized weights for vLLM.
* Before serving, the QLoRA adapter is QuaRot-rotated to fit the `w8a8` checkpoint that
  was QuaRot-rotated with [msmodelslim](https://gitcode.com/Ascend/msmodelslim).
* Opt-in QLoRA memory optimizations (`--bnb-dequant-patch`, `--expert-dequant-recompute`,
  `--expert-chunk-size N`, all off by default) save 3.4-4.8 GB/card and raise the max
  context on one node to 14336.

## Layout

- `accuracy_eval/` — vLLM serving + evalscope benchmarks (see its README).
  * `eval_pipeline.sh` — one-shot accuracy evaluation (server + GSM8K + MATH-500 + shutdown).
- `data/` — teacher responses on GSM8K + MATH; GSM8K test set.
- `installation/` — container and dependency setup.
- `LoraAdapterTransformer/` — mcore->HF LoRA converter (git-ignored, cloned by the installer).
- `MindSpeed-LLM/` — the fork (branch `dev/qlora_support`).
- `models_ds/` — checkpoints and adapters (git-ignored).
- `scripts_qlora/` — the training pipeline scripts: dequant, NF4 conversion, training,
  HF export, rotation.
  * `full_train_pipeline.sh` — runs all steps.
- `utils/` — data preparation, checkpoint checks, adapter export, QuaRot rotation.
  * `utils/quantization/` — w8a8 quantization scripts and configs.

## Prerequisites

- One Ascend node, 8x 910B3 64 GB, ~750 GB free.
- FP8 Base checkpoint in `/data/models/DeepSeek-V4-Flash-Base`, w8a8 checkpoint in
  `/data/models/DeepSeek-V4-Flash-Base-w8a8`, teacher tokenizer in
  `/data/models/DeepSeek-V4-Flash-0731-bf16`.
- va30 containers (CANN 9.2.0): `th_va30_qlora_train` for everything except serving,
  `th_va30_qlora_infer` (MoE-LoRA patched vllm-ascend 0.30) for serving/eval.

## Setup

1. Create the training and inference containers with `installation/create_container.sh`:
   ```bash
   STAGE=train bash installation/create_container.sh
   STAGE=infer bash installation/create_container.sh
   ```
2. Inside the training container (first launch only):
   ```bash
   bash installation/prepare_train_container.sh
   ```
3. Inside the inference container (first launch only):
   ```bash
   bash installation/prepare_eval_container.sh
   ```

## Train

```bash
bash scripts_qlora/full_train_pipeline.sh
```

The pipeline calls the following steps, which can also be run by hand (each refuses to
overwrite existing output):

1. `utils/prep_shuffled_distill_ds.sh` — shuffle + tokenize the teacher dataset (~2 min).
2. `scripts_qlora/dequant_base_fp8_to_bf16.sh` — FP8 Base -> bf16 (~80 min, ~570 GB).
3. `scripts_qlora/ckpt_convert_deepseek4_flash_base_ep4_pp2_qlora.sh` — bf16 HF -> NF4
   mcore format (EP4/PP2/TP1).
4. `scripts_qlora/qlora_finetune_deepseek4_flash_base_distill_1epoch.sh` — training,
   221 iterations (~4.5 h). Use `SMOKE=1` for a 5-iteration check in a separate output dir.
5. `scripts_qlora/export_mcore2hf.sh` — adapter export to HF/PEFT (unrotated), CPU only.
6. `scripts_qlora/rotate_adapter.sh` — QuaRot rotation for vLLM serving on Base-w8a8
   (CPU, ~22 min).

### Training recipe (in the training script)

- full model, EP4/PP2/TP1, MBS 1 / GBS 64, 221 iters (one epoch), seq 4096;
- LoRA r16 / alpha 32 on `linear_fc1 linear_fc2`, lr 3e-4, seed 42, `--seq-aux`
  (0.001) with `--moe-router-load-balancing-type none`;
- fused lightning indexer / mHC / sparse flash attention flags on (eager fallbacks exist),
  full uniform recompute, swap optimizer, variable-length samples (`NOPAD=1`).

## Evaluate

Inside the inference container:

```bash
bash accuracy_eval/eval_pipeline.sh          # untuned Base-w8a8
LORA=1 bash accuracy_eval/eval_pipeline.sh   # trained rotated adapter (default LORA_PATH)
```

Starts the vLLM server, runs full GSM8K and MATH-500 (both greedy, thinking off), stops
the server. Results in `accuracy_eval/logs/<model>/{gsm8k,math_500}/`. For manual
serving: `serve_ds_w8a8{,_lora}.sh` + `evalscope_direct.sh`.

## Notes

- **peft must be 0.20.0.** With peft >= 0.21 the routed-expert LoRA silently freezes and
  only the shared expert trains. The training container installer pins it.
- Master's own `--save-lora-to-hf` rejects grouped-GEMM experts — adapter export goes
  through `LoraAdapterTransformer` (`scripts_qlora/export_mcore2hf.sh`).
- If you want to train on the `w8a8`-dequantized base instead, use
  `scripts_qlora/dequant_w8a8_to_bf16.sh`; the result is already in the rotated basis, so
  skip `rotate_adapter.sh` for such adapters.
- Launch long jobs detached (`docker exec -d ... > log 2>&1`), never with a foreground
  `docker exec` — SSH drops kill foreground jobs.
